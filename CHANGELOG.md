# Changelog

Все значимые изменения этого пакета документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

## [0.3.2] — 2026-09-10

### Исправлено

- **Порядок блоков в админке.** `ContentBlocksResource` не задавал колонку сортировки, и MoonShine подставлял свой дефолт `id desc`: таблица блоков в форме владельца показывала блоки от новых к старым, а результат перетаскивания после перезагрузки страницы «пропадал». Ресурс сортирует по `sort_order asc` с добивкой по `id` для строк с одинаковой позицией.
- **Порядок на связи `contentBlocks()`.** Связь теперь отдаёт блоки по позиции (`orderedBySort()`, затем по ключу), как это делала прикладная `Page::blocks()` до переезда в пакет; preview-режим `HasMany` и прикладной код получают тот же порядок, что и рендерер.

### Изменено

- Требуется `ewk/moonshine-resource-kit` ^0.1.1: в 0.1.0 асинхронные методы `reorder` / `massActivate` получали пустой запрос и молча ничего не делали.

## [0.3.1] — 2026-09-10

### Исправлено

- **Утечка запроса между HTTP-запросами под Octane.** `BlockOwnerResolver` (синглтон) получал контейнер в конструктор; под Octane это базовое приложение воркера, а не песочница текущего запроса. Резолвя через него `CrudRequestContract`, резолвер оставлял `MoonShineRequest` формы страницы в базовом приложении, и последующие запросы того же воркера видели чужой ресурс: сохранение блока из встроенной формы валидировалось правилами формы владельца («Значение поля Название должно быть массивом», «The selected Тип is invalid»). Контейнер и запрос теперь берутся в момент вызова.

## [0.3.0] — 2026-09-09

### Добавлено

- **Категории блоков.** `BlockContract::category()` группирует блоки в селекторе типа (`<optgroup>`); `null` оставляет блок без группы. `BlockRegistryInterface::options()` теперь возвращает вложенные группы `категория => [код => название]`.
- **Области применения блоков.** `BlockContract::scopes()` перечисляет владельцев, которым доступен блок (пустой список — всем); владелец объявляет свою область через новый `ScopedBlockOwnerContract::blockScope()`. Форма блока показывает и валидирует только доступные типы и строит только их поля; `BlockRegistryInterface::availableFor()` и `optionsFor()` отдают тот же набор для своих ресурсов.
- **`BlockOwnerResolver`.** Определяет владельца формы блока: по редактируемому блоку, по отправленным morph-ключам (`blockable_type` / `blockable_id`) или по родительскому элементу встроенной HasMany-формы.

### Изменено

- `BlockFieldsBuilderInterface::build()` принимает необязательный список кодов, ограничивающий собираемые типы.
- `AbstractBlock` реализует `category()` (`null`) и `scopes()` (`[]`) по умолчанию; блоки, реализующие `BlockContract` напрямую, должны добавить оба метода.

## [0.2.2] — 2026-09-08

### Исправлено

- **Одинаковые колонки у разных типов.** MoonShine переключает видимость полей по имени инпута, поэтому поля разных блоков с одной колонкой (`title`) конфликтовали: поле чужого типа оставалось видимым, а его значение терялось. Каждое поле получает `data-show-when-field` вида `content.{code}.{column}`.

## [0.2.1] — 2026-09-08

### Исправлено

- **Сохранение блока из админки.** Колонка `content` теперь кастуется в `AsArrayObject`: форма MoonShine пишет вложенные ключи через `data_set($model, 'content.heading', ...)`, и с обычным `array`-кастом сохранение падало с «Indirect modification of overloaded element». `contentData()` по-прежнему отдаёт обычный массив.

## [0.2.0] — 2026-09-08

### Добавлено

- **Laravel 13.** Пакет объявляет совместимость с `laravel/framework` `^12|^13` (тесты — `orchestra/testbench` `^10|^11`).
- **Точечные колонки полей.** Поля блока могут адресовать вложенные ключи контента через точку (`body.en` → `content.body.en`): значения подставляются в форму через `Arr::get`, а фильтр контента считает корневой ключ (`body`) принадлежащим блоку.

### Исправлено

- **Применение полей чужих типов.** Форма отправляет поля всех зарегистрированных блоков сразу; теперь применяются (и трогают загруженные файлы) только поля типа, выбранного в отправленной форме (`canApply`), а не всех типов подряд.

## [0.1.0] — 2026-07-07

Первый публичный релиз: полиморфные контент-блоки для Laravel 12 с админкой на MoonShine 4.

### Добавлено

- **Полиморфное подключение блоков.** Упорядоченные, переключаемые и хранящиеся в JSON блоки цепляются к любой Eloquent-модели через morph-связь `blockable` (страницы, товары, категории — что угодно) с помощью трейта `HasContentBlocks` и контракта `HasContentBlocksContract`.
- **Два типа блоков.** *Статические* — данные берутся из сохранённого JSON-контента; *динамические* — данные вычисляются в момент рендера через внедряемые в конструктор зависимости (списки товаров, коллекции, фиды).
- **Рендерер блоков.** `BlockRenderer::render($model, $request)` отдаёт структурированный payload: неактивные блоки пропускаются, порядок соответствует drag & drop, каждый блок оформлен как конверт `{ id, code, name, data }`. Строки с незарегистрированным типом пропускаются с событием `UnknownBlockTypeEncountered`.
- **Реестр блоков.** Разрешение блоков через контейнер (`BlockRegistryInterface`), без фасадов и глобального состояния; метод `override()` для замены упакованного или прикладного блока (случайные коллизии кодов бросают исключение).
- **Админка MoonShine 4.** Ресурс с пер-типовыми полями формы, drag & drop сортировкой и инлайновым переключением активности (на базе [ewk/moonshine-resource-kit](https://github.com/einzelwerk/moonshine-resource-kit)), а также встраиваемое поле `ContentBlocksField` для формы любого ресурса — возвращает обычный `HasMany`, поэтому все его опции остаются доступны.
- **Валидация контента блока.** Метод `rules()` с ключами относительно контента блока — пакет сам добавляет нужные префиксы. Внутриблочные условия полей через `contentColumn()`.
- **Artisan-команда `make:content-block`** для генерации статических и динамических (`--dynamic`) блоков.
- **Конфигурация** (`config/content-blocks.php`, публикуется тегом `content-blocks-config`): подмена модели, выбор ресурса MoonShine, типы владельцев для селектора `blockable_types`.
- **Точки расширения:** кастомная модель `ContentBlock`, ребинд `BlockFieldsBuilderInterface`, собственный админ-ресурс, реакция на осиротевшие строки через слушатель `UnknownBlockTypeEncountered`.

### Требования

- PHP >= 8.3
- Laravel ^12
- MoonShine ^4.15
- ewk/moonshine-resource-kit ^0.1
